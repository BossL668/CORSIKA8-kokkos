API reference

This reference presents the main integration interfaces directly from their C++ headers. Doxygen extracts declarations and comments; Breathe renders them in the guide. Function names, template parameters, argument types, defaults and return types come from source rather than manually copied signatures.

Note

Source baseline: d5297c43. These are the implementation’s current interfaces, not an upstream API proposal or a blanket compatibility guarantee. Available implementations depend on the configured targets and execution backends.

The pages select the interfaces used to connect components and explain their roles before the generated declarations. They do not reproduce every helper or every diagnostic member. Source links provide the complete headers; the component chapters describe call order, memory accessibility, units, ownership and supported domains. The alphabetical index and site search include the rendered API names.

Interpreting a declaration

A reference or pointer does not transfer ownership. Check the documented lifetime of the referred object and whether the function is a host adapter, a data transfer or a device-callable calculation. Similarly, a result record may require checking a status before its numerical values are valid. A header’s presence does not establish that a particular optional target has been built or validated on a device.

The API pages retain source comments and add links to the relevant component contracts. Where a source declaration lacks detailed parameter documentation, use those contracts and the implementation; no additional behavior is inferred from the function name. In particular, validation batch wrappers and resident production execution can expose similar calculations with different storage and completion costs.

Building and updating the reference

The documentation build extracts the public corsika/kokkos headers without compiling the application or its physics dependencies. It does not execute the interfaces. Use the documentation build instructions for the tool requirements and commands.

The generated-header manifest records the Doxygen version, input-header hashes and extraction configuration hash for this build. Types with their own reference entry link within the guide; additional implementation types link to their source declarations where the reference can be resolved.

When adding or changing an interface, update its declaration-level contract and the relevant API page together. Regenerate the reference and review overloads, template signatures, public member visibility and links. The source extraction and the semantic guide answer different questions; both must remain consistent with the implementation.
