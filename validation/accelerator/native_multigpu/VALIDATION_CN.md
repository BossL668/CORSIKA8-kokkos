# 原生多 GPU 入口回归记录（2026-09-24）

本轮只把已有的多 GPU 调度/合并流程改写为 C++，集成进原有
`c8_air_shower`。没有修改输运或射电物理算法。不传 `--devices`
时仍走原单卡/OpenMP 路径。测试不替代 500 例物理统计验收。

## 已通过

1. C++ fixture 测试：四个独立 worker、连续两例、空分片、重复根标签、
   带符号射电场合并、粒子拼接/首反应记录、配置与网格冲突、NaN、
   重复 GPU 别名、失败退出、超时、SIGTERM 中断、子进程回收和带空格路径。
   `ctest`：1/1 通过（测试内包含上述检查）。四 worker 是进程测试，
   不代表四张真实 GPU 已验收。
2. 本地 NVIDIA GeForce RTX 4060 Laptop GPU：10 GeV 光子，无 EM 薄化，
   内置天线环，显存预算 20%。原生入口连续完成两例，种子
   26092441、26092442；第一例与旧 Python 协调器使用同一二进制和条件，
   分片记录/哈希一致，七类 Parquet 表所有列逐项相等。
3. 单卡 CUDA 与 OpenMP（1 thread）各用种子 26092443，对比修改前备份
   二进制与新二进制：相同七类输出逐项相等，最大绝对差为 0。
4. 安装后再跑种子 26092444：将 PATH 限制为 `/usr/lib/wsl/lib`
   （无 Python 可执行程序），原生入口正常完成，耗时 14.8794 s。
   该数值仅是安装运行检查，不能用于多卡加速比。CoREAS/ZHS 输出非零。

七类输出为 longitudinal profile、production profile、能量沉积、
CoREAS、ZHS、观测面粒子、首次相互作用。小能量检查的观测面粒子表为空，
非空粒子拼接另由 fixture 测试覆盖。
