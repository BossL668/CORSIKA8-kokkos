Host and backend conversion

Two host-side interfaces convert particle data. The general helpers update physical values in an existing record or particle. The production router’s transfer functions additionally handle identity, logical nodes and native stack insertion. Both use the numerical conventions in Particle representation and numerical conventions; neither performs a transport step.

Value-conversion interface

ParticleConversion.hpp declares the following template functions, implemented in ParticleConversion.inl:

Function

Inputs

Result and mutation

export_particle_values

Native particle, common CoordinateSystemPtr, existing ParticleState&.

Returns void. Replaces PID, total energy, position, direction, time and weight; preserves all metadata fields.

import_particle_values

ParticleState const&, the record’s coordinate system, existing native particle reference.

Returns void. Updates physical values, converting total to kinetic energy; does not insert an entry or restore identity/node metadata.

The export’s unit and coordinate conversion is:

51    auto const position = particle.getPosition().getCoordinates(coordinateSystem);
52    auto const direction = particle.getDirection().getComponents(coordinateSystem);
53    auto const pid = static_cast<std::int32_t>(particle.getPDG());
54    double const energy = particle.getEnergy() / 1_GeV;
55    double const time = particle.getTime() / second;
56    double weight = 1.;
57    if constexpr (particle_conversion::HasWeightGetter<TParticle>::value) {
58      weight = particle.getWeight();
59    }
60
61    state.pid_ = pid;
62    state.energyGeV_ = energy;
63    for (int axis = 0; axis < 3; ++axis) {
64      state.positionM_[axis] = position[axis] / meter;
65      state.direction_[axis] = direction[axis].magnitude();
66    }
67    state.timeS_ = time;
68    state.weight_ = weight;

Both helpers require a non-null coordinate system. Import checks the PDG conversion, rejects total energy below the C8 rest mass, and rejects a non-unit weight when the destination has no weight setter. Those checks precede physical-value mutation. Finite values and appropriate directions remain caller preconditions; this is not a complete particle validator.

Complete production transfer

The following functions belong to corsika::kokkos::particle_transfer in RouterParticleConversion.hpp and RouterParticleConversion.inl. They implement the production transfer directly rather than calling the general helpers above.

to_device_state

The function receives a native particle, the common coordinate system, explicit historyId, parentHistoryId, generation and stepId values, and an EnvironmentTopology. It returns a ParticleState by value without changing or removing the source particle.

It exports physical values, copies the supplied identity and calls export_logical_node. That function maps particle.getNode() to the exported tree’s index and rejects a missing or unmapped node. It does not repeat a position-containment search.

mediumId_ is not populated by this conversion function. After checking the environment state, EmRouter::stage obtains it from the selected node’s model. The end of that staging operation is:

129      state.mediumId_ = environment_.getModel(state.environmentNode_)->mediumId_;
130      auto const previous = lastCpuExpansionStates_.find(state.historyId_);
131      if (previous != lastCpuExpansionStates_.end() &&
132          sameTransportState(previous->second, state)) {
133        forceSmallBatchToGpu_ = true;
134      }
135      staged_.push_back(state);

The host loop erases the native stack entry after staging succeeds. See Hybrid event execution for the routing and ownership transition.

import_particle

This function receives the destination stack, a numerical record, its common coordinate system and the matching topology. It converts the PDG code, checks the rest-mass boundary, constructs C8 geometry values, inserts a new stack entry and restores identity, weight and the native node pointer. It returns the newly inserted particle handle.

The final insertion and metadata restoration are:

 96    auto particle = stack.addParticle(std::make_tuple(code, totalEnergy - mass, direction,
 97                                                      position, state.timeS_ * second));
 98    particle.setTransportIdentity(transport::TransportIdentity{
 99        state.historyId_, state.parentHistoryId_, state.generation_, state.stepId_});
100    set_weight_if_supported(particle, state.weight_);
101    import_logical_node(particle, state, tree);
102    return particle;

This operation requires a valid record and matching topology. It is not a transactional validator: node restoration and some metadata checks occur after insertion. The value-only helper’s pre-mutation checks must not be assumed to apply to this complete-transfer function.

Logical nodes and environment lifetime

EnvironmentTopology maps native node addresses to exported indices and back. Import restores the recorded logical node, even when the position could geometrically belong to another nested node. Recomputing the node from position alone would discard the tracking state carried across a boundary.

The native environment and topology must remain valid throughout transfer. Node indices have meaning only within the corresponding exported tree; mediumId_ cannot reconstruct a native node. Coordinator frontier import also checks the exported environment fingerprint before accepting logical indices; see Bounded frontier import.

Transport identity and step state

TransportIdentityStackExtension.inl assigns each primary a history ID and assigns each secondary a new ID, its parent’s ID and the next generation. Copy and swap operations move the identity with the particle. Import restores the supplied identity and advances the allocator when necessary to avoid reusing an imported ID.

The step counter has a specific convention:

151  template <typename TParentStack>
152  inline StepId TransportIdentityDataInterface<TParentStack>::beginTransportStep() {
153    StepId const currentStep = getStepId();
154    if (currentStep == std::numeric_limits<StepId>::max()) {
155      throw std::overflow_error("Transport step ID space exhausted");
156    }
157    getStackData().setStepId(getIndex(), currentStep + 1);
158    return currentStep;
159  }

beginTransportStep() increments the stored counter and returns its previous value. CpuParticleScheduler::acquireNext carries that returned value in the scheduled particle; the router receives it explicitly. Replacing it with a later call to getStepId() would change the exported step identifier.

History IDs are not stack indices, queue indices or thread identifiers. They support ancestry, step tracking and random-stream selection across routing and compaction. Preserving them is necessary for reproducibility, but does not by itself guarantee identical histories after changing the scheduling or random-stream policy.

Return-path responsibilities

The caller determines whether a returned state requires a native step, completion of a selected interaction, a forced decay or cut processing. These policies are described in Batch execution and CPU return paths; conversion does not make that decision.

In particular, a compatibility-tagged muon-pair product below its rest mass must receive the existing native-cut handling before ordinary stack import. reserved_ does not relax the importer’s rest-mass check. Conversion also does not normalize a direction, draw a random number or repair a physical state; those actions belong to their explicitly defined transport or validation paths.
