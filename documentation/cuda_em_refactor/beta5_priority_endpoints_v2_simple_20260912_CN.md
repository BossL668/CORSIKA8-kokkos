# CPU 优先简化控制：cpu-primary-v2-simple

实验修改，仅影响显式 `openmp-cuda`。原 `cuda-openmp`/legacy、单 CUDA、
单 OpenMP、标量 PROPOSAL、其他 adaptive 分支与山体物理代码不改变。
源代码已修改不等于性能验收通过；生产 install 未替换。

## 为什么简化

CPU 优先v1的PSR首例394.830s，比纯OpenMP130的139.155s慢。v1在CPU某
类队列小于完整容量时，可能立即取回刚按吞吐比例分给GPU的待处理工作。
这使“分配”与“补齐”两条规则相互抵消，不应直接把高占用解释为有效吞吐。
v1还启用profile分片与指定回退合批，使速度差不只是来自双端调度。

## 简化规则

1. 保留两个有界独立队列、原history租约、独立CUDA驱动及恰好一次提交。
2. 新粒子先留出CPU有效批量。GPU初始份额1/16，此后仅用原双端已有的
   photon/lepton逐类吞吐移动平均计算份额。没有额外的完成时间预测模型。
3. CPU只有完全没有本端工作时才取回GPU的安全队列；GPU只有空闲时才取
   CPU剩余工作的一个吞吐份额。禁止访问在途CUDA的设备队列。
4. 不再按吞吐比计算GPU单次输入上限；两端都用各自原arena容量。CPU轻子
   沿用单端1024波前上限及原min-batch返回阈值，GPU辅助轻子使用8波前上限。
   这是固定安全交接边界，不是粒子时间cut，也不改变物理步长。
5. 本轮取消CPU优先专属profile分片和回退合批，沿用原legacy/单端调用路径。
   共享物理kernel、PROPOSAL表、射电公式、随机数函数、cut/thinning均不变。

长CPU调用可能令小GPU提前完成后等待服务，这是辅助端优先级的代价，
没有声称实现“GPU驱动无限自主续跑”。是否有净收益必须与纯OpenMP实测。
动态调度仍可能改变history分配时序，不承诺不同模式同seed产生同一棵树。
