Physics tables and transport stages

These declarations connect configured native models to numerical queries and individual particle stages. They are generated from the public headers at the baseline recorded in API reference. Host preparation owns and validates data; numerical functions borrow accessible arrays and return records or status. They do not own the surrounding scheduler.

For the complete preparation chain, supported processes and array layout, see Physics models and table preparation. For the ordering of sampling, propagation, scattering, vertex selection and final-state production, see Transport and interaction kernels.

Native export and ownership

The exporter receives views of native calculators already configured by C8. The resulting host table owns the copied interpolation state. Uploading it creates a separate execution-space owner; the returned numerical view borrows that owner’s arrays. A table-view name does not imply that its pointers are accessible on every device.

Sources: NativeTableExporter.hpp, ProposalNativeTable.hpp and NativeTableStorage.hpp. Cache identity and runtime lifetime are described in Model selection, preparation and reuse and Table representation and device storage.

template<typename TExecutionSpace>
class NativeTableStorage

Own an immutable native-table copy in one execution space’s memory.

Initialization validates the canonical export and its content hash before checking the memory budget or allocating arrays. It publishes a numerical view only after the original upload order and completion fence. Allocation failure resets partial storage. No PROPOSAL object enters device memory.

Initialize the Kokkos runtime before constructing this storage, and keep it initialized until the storage is destroyed. A copied storage object shares immutable allocations; a returned view does not own them. Finish all kernels using a view before resetting or releasing its last owner.

Native query results and units

The following queries use total energies in MeV and grammage in g/cm². Rates are per g/cm²; the loss-fraction result is dimensionless. These units are distinct from particle-state total energies in GeV. Callers inspect the returned status before using the value. Query records also retain iteration diagnostics; they do not own table storage.

The cumulative-rate query takes the table’s transformed loss coordinate. The inverse query instead takes a quantile and returns a physical loss or secondary-energy fraction according to its photon_split argument. The independent total-rate spline is used for distance sampling; ordered channel selection has its own rate-summation query. See Table representation and device storage for those distinctions.

Sources: ProposalNativeData.hpp and ProposalNativeQueries.hpp. The declarations below select the principal query boundaries; the header also provides individual-column, stopping-power, range and selection-total queries.

Selection and propagation

Selection produces a candidate interaction record without advancing the particle. Transport then resolves the competing limits and returns the completed step or an explicit failure/completion request. The charged-lepton transport function does not itself execute multiple scattering or a discrete final state. Its applyMoliere argument also controls the zero-length-cut status consumed by the later scattering stage.

These functions are numerical entry points, not host queue-submission calls. The caller supplies exclusive output slots and keeps all borrowed table and environment data alive in accessible memory. The meaning of partial records and return flags is part of the interface; a fallback record does not execute the CPU handler. See Candidate sampling and vertex selection, Charged-lepton propagation and Batch execution and CPU return paths.

Sources: InteractionSelection.hpp, LeptonTransportStep.hpp and PhotonTransportStep.hpp.

inline InteractionSelectionOutcome corsika::kokkos::select_discrete_interaction(InteractionPhysicsView const &physics, ParticleState const &particle, std::uint64_t const input_index, std::uint64_t const random_seed, std::uint64_t const shower_id)

Sample interaction grammage and preserve production random provenance. Charged particles defer channel selection until after continuous loss. template<typename TEnvironmentView>
std::uint32_t corsika::kokkos::transport_lepton(ContinuousPhysicsView const &table, bool applyMoliere, TEnvironmentView const &environment, TransportGeometryConfig const &config, InteractionRecord const &interaction, LeptonTransportRecord &record, FallbackRequest &fallback, ExternalTransportBoundary const external = {})

Advance one charged lepton using the production environment-tree path. The caller provides read-only native continuous tables, an exported tree and an independently configured observation plane in one coordinate system. table and environment owners must outlive the call/kernel in accessible memory. Step competition uses start-tangent grammage; continuous loss uses the completed endpoint chord. No scattering draw, discrete final state or CPU handler runs here.

Parameters:

  • table – Borrowed native continuous tables and kinetic transport cuts in MeV.

  • applyMoliere – Whether the later split scattering stage will run.

  • environment – Read-only, validated C8 environment-tree snapshot view.

  • config – Query limits, separate observation plane and diagnostic origin.

  • interaction – Previous sampled-distance, selected, no-interaction or cut record.

  • record – Exclusive output slot; retained unchanged or partly written on failure.

  • fallback – Exclusive failure slot; only written when returning 1.

  • external – Optional non-absorbing material-interface distance candidate.

Returns:

0 for success, 1 for explicit CPU fallback, or 2 for a successful zero-length cut that must bypass split scattering (then be normalized to 0). Input and output objects must not alias. Inspect the return value before using record; no new rollback or output clearing is added to the production policy.

template<typename TEnvironmentView>
PhotonTransportOutcome corsika::kokkos::transport_photon(TEnvironmentView const &environment, TransportGeometryConfig const &config, InteractionRecord const &interaction, ExternalTransportBoundary const external = {})

Advance one selected photon on the production environment-tree path.

Input state and geometry are read-only. The step retains original boundary competition, same-value ordering, straight grammage inversion and time cuts. No RNG draw, reaction final state, observation output or CPU replay is executed. On failure a partial record may exist: callers must inspect fallbackFlag_.

Parameters:

  • environment – Validated snapshot arrays, alive throughout the call/kernel.

  • config – Query parameters, independent observation plane and diagnostic origin.

  • interaction – Selected, no-discrete-interaction or pre-cut record.

  • external – Optional external straight material interface.

Returns:

Complete step or the unchanged production fallback reason/diagnostics.

Final-state classification and materialization are separate public stage interfaces in LeptonFinalStateStep.hpp and PhotonFinalStateStep.hpp. Their counting, exclusive-slot assignment, CPU completion and energy-accounting contracts are documented in Photon transport and interaction completion.
