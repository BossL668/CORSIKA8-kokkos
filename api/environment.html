Environment preparation and queries

The environment interfaces separate native-scene export, numerical storage and per-query results. Host preparation accepts the existing C8 tree and coordinate system; device queries operate on accessible exported arrays. The declarations below are generated from the public headers. Supported shapes, model kinds and shared search semantics are described in Scene construction and snapshot export, Environment queries and boundary selection and Supported models and extension requirements.

Host snapshot and topology

The snapshot owns independent numerical records in one common coordinate system. Its topology also retains borrowed mappings to native nodes and models. Exporting the numerical arrays does not transfer those host pointers to the device. Keep the native objects alive and unchanged while their mappings are used; rebuild after changing the scene.

Sources: EnvironmentSnapshot.hpp, EnvironmentTopology.hpp and EnvironmentPreparation.hpp.

template<typename TModelProperties>
class EnvironmentSnapshot

Host-owned assembly of topology, shapes and exact native model parameters.

Each node has one shape at the same index in getShapes(). A nonnegative EnvironmentNode::modelIndex_ addresses getModels(); -1 means no model, with no automatic inheritance from the parent. Model indices follow first occurrence in native preorder. Nodes sharing the same property object share one model and composition range; equal-valued distinct objects stay distinct. Child and exclusion ordering, including repeated references, is preserved.

Numeric records are independent copies in one caller-selected coordinate system. The topology still borrows native node/model pointers: keep the source tree and model assignments alive and unchanged while using those mappings. Copies retain the same borrowed source and shared coordinate system. Rebuild after changing geometry, models or their coordinate systems. Only the numeric arrays, not this host object or its pointers, may be copied to a device. Their layout is not a portable serialization format.

Performs no containment search, density evaluation, boundary intersection or observation-surface construction. Unsupported inputs fail explicitly; nodes and models are never silently omitted or replaced by approximations.

template<typename TModelProperties>
class EnvironmentTopology

Host-only export of C8’s ownership tree and ordered exclusion references.

Owns the numeric arrays, but borrows the native node and model pointers. The source tree and its model assignments must remain alive and unchanged while this mapping is used; rebuild it after modifying the environment. Indices are deterministic preorder indices within this snapshot, not IDs that survive edits of the source tree. Copies retain the same borrowed source. Only the numeric arrays, never this object, may be copied to a GPU.

All nodes are retained, including nodes without model properties. Distinct nodes sharing a property object share a model index but keep separate node indices. Equal-valued but distinct models are not merged. Exclusion edges remain directed and ordered, including repetitions or reciprocal edges. No containment search or geometrical validity check is performed here.

Resident ownership and data views

bind_environment_data borrows host addresses from a snapshot. EnvironmentStorage uploads those arrays and owns the resident allocations. The same EnvironmentDataView type can contain host or device addresses; the type itself does not establish accessibility. Its owner must outlive all operations using the view. See Device-code contracts and portability for ordering and memory-space requirements.

Sources: EnvironmentDataView.hpp, EnvironmentSnapshotData.hpp and EnvironmentStorage.hpp.

struct EnvironmentDataView

Borrowed numeric arrays of one exported environment, without native pointers.

Nodes and shapes have the same count and index order. All arrays must belong to one valid snapshot and be accessible from the execution space using them. This record neither owns storage nor extends its lifetime. Its owner must remain alive and unchanged until all work using the record has completed. Native byte layout is not a portable serialization format.

template<typename TModelProperties>
EnvironmentDataView corsika::kokkos::bind_environment_data(EnvironmentSnapshot<TModelProperties> const &snapshot)

Borrow the host numerical arrays of an already exported native environment.

No allocation, re-export, coordinate conversion or topology search occurs. The snapshot guarantees valid counts and same-index node/shape arrays. Native node/model pointers and coordinate-system handles are not included. Keep the snapshot alive and unchanged until the synchronous storage upload finishes. The returned pointers are host addresses, not device addresses.

template<typename TExecutionSpace>
class EnvironmentStorage

Own the device arrays uploaded from an already exported host environment.

Retains production FullEnvironmentOwner’s allocation, mirror and deep-copy sequence. Shapes are a separate same-index array in the receiving layout. No topology search, model evaluation or environment re-export happens here. Copies share Kokkos allocations; borrowed data views do not own them. Drain the caller’s execution before replacing or releasing the last owner, and release all owners before Kokkos finalization.

Query configuration and results

Environment queries return status with the numerical result. Preserve both: a failure or out-of-range status may retain a nonfinite raw value. Node indices refer to this snapshot, not to a medium identifier. Positions and lengths use metres; density uses g/cm³ and grammage uses g/cm². The grammage result record is also used for inverse length queries, as its declaration specifies.

Source: EnvironmentQuery.hpp.

Numerical queries

These functions assume valid exported arrays. The logical-node argument distinguishes an already assigned node from a request for point location. The straight-boundary query does not include the independent observation plane. Grammage and its inverse do not truncate their segment at a boundary; step-limit competition remains the caller’s responsibility.

template<typename TEnvironmentView>
inline EnvironmentLayerQuery corsika::kokkos::query_environment(TEnvironmentView const &environment, EnvironmentQueryConfig const &config, double const (&positionM)[3], double const *direction = nullptr, std::int32_t logicalNode = -3)

Query a node and its local density in an exported environment tree.

A node without its own model is outside the supported material environment; no parent properties are inherited. This API covers exported node trees, not the legacy sphere-layer or convex-polyhedron compatibility paths. Callers must explicitly route unsupported environments through their original path.

Parameters:

  • environment – Complete read-only exported arrays, with valid topology, supported shapes and model kinds. No per-query scan validates those arrays.

  • config – Maximum magnetic deflection must be finite and in (0, pi/2).

  • positionM – Position in metres in the snapshot’s common coordinate system.

  • direction – Optional finite, unit direction in the same system.

  • logicalNode – -3 requests location from the root. Any other value is an already-assigned node identity and is not replaced by geometric location.

Returns:

Original status, logical node and density, including failure values.

template<typename TEnvironmentView>
inline EnvironmentBoundaryQuery corsika::kokkos::distance_to_environment_boundary(TEnvironmentView const &environment, EnvironmentQueryConfig const &config, double const (&positionM)[3], double const (&direction)[3], std::int32_t logicalNode = -3)

Query the same node, then select its nearest ordered straight boundary.

positionM, direction and logicalNode follow query_environment(). The unit direction makes the trajectory parameter a length in metres, not time. The independent observation plane does not participate in this search.

template<typename TEnvironmentView>
inline EnvironmentGrammageQuery corsika::kokkos::environment_grammage(TEnvironmentView const &environment, EnvironmentQueryConfig const &config, std::int32_t nodeIndex, double const (&positionM)[3], double const (&direction)[3], double distanceM)

Integrate one assigned model along a straight segment, in g/cm^2.

nodeIndex selects a model without location or inheritance. positionM is in metres, direction is dimensionless and unit length, and distanceM must be finite and nonnegative. The sliding-planar radial axis is frozen at the starting point. No boundary clipping or additional position check is made. Preserve status and value together: an out-of-range result retains its raw value, which may be nonfinite. A selected physical step needs a finite value.

template<typename TEnvironmentView>
inline EnvironmentGrammageQuery corsika::kokkos::environment_arclength(TEnvironmentView const &environment, EnvironmentQueryConfig const &config, std::int32_t nodeIndex, double const (&positionM)[3], double const (&direction)[3], double grammageGPerCm2)

Invert the same assigned model’s grammage, returning length in metres.

Coordinates and direction follow environment_grammage(); grammageGPerCm2 must be finite and nonnegative. No boundary truncation is performed. An unreachable finite length returns GrammageOutOfRange and the original raw inverse result, rather than silently substituting zero or a finite limit.

template<typename TEnvironmentView>
inline EnvironmentGrammageQuery corsika::kokkos::geometry_competition_grammage(TEnvironmentView const &environment, EnvironmentQueryConfig const &config, std::int32_t nodeIndex, double const (&positionM)[3], double const (&direction)[3], double distanceM)

Grammage of a geometry candidate, retaining the production overflow sentinel.

Only the original positive, growing exponential conditions permit a finite candidate length with infinite grammage to return Success. Positive infinity is a comparison sentinel, not an acceptable traversed depth for a selected physical step. The ordinary environment_grammage() policy remains unchanged. This node-tree rule is independent of any external-boundary enable flag; legacy non-tree external-boundary options are outside this API’s domain.

The geometry-candidate function retains the production positive-infinity comparison sentinel under its documented exponential-profile conditions. That sentinel must not be consumed as the finite traversed depth of a selected physical step. Curved boundary selection and the observation-plane path are documented separately in Environment queries and boundary selection.
