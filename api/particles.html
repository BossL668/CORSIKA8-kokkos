Particle records and conversion

These declarations define the numerical particle state, storage views and native C8 transfer boundary. Signatures and member descriptions are generated from the public headers at the API reference’s source baseline. The transfer operations are host functions; storage accessors marked for device use still require accessible allocations and valid indices.

The behavioral descriptions are in Particle representation and numerical conventions, Host and backend conversion and Device storage and state updates.

Value records

ParticleState stores total energy in GeV, positions in metres, time in seconds and dimensionless directions in the selected common coordinate system. Its history and logical-node fields are part of the transport state. StepRecord carries an output segment, with unweighted deposits; it does not update a profile or apply the statistical weight by being copied.

Sources: ParticleState.hpp and StepRecord.hpp.

struct ParticleState

Value-only particle data at the host/device transport boundary.

Positions and directions use the common coordinate system selected by the conversion boundary. This record stores neither coordinate-system objects nor host pointers, and performs no conversion, normalization or physics operation. Public members deliberately retain aggregate initialization and direct device access. The type is standard-layout and trivially copyable, but its padding and native byte order are not a portable serialization format.

struct StepRecord

Value-only transport segment for host/device exchange and output adapters.

Endpoint positions use the same common coordinate system as ParticleState. Energies are in GeV, positions in metres and times in seconds. Deposits are unweighted; the output adapter applies weight_ once. Copying a record neither deposits energy nor allocates a particle/step identifier.

Public members preserve aggregate access. This standard-layout, trivially copyable type has no explicit alignment requirement beyond its members and is not a portable wire format. No Kokkos or physics-library header is required.

Field storage and borrowed access

ParticleSoA owns field arrays in the requested memory space. Its raw view borrows the same allocations and preserves vector-field strides. A raw view neither transfers data nor retains the storage owner. Complete outstanding uses before releasing or replacing that storage. Queue progression is a separate responsibility described in Device storage and state updates.

Physical-value conversion

These host functions convert values into or out of an existing record or native particle. They do not allocate transport identities or establish the logical-node mapping. The production transfer operations below cover those additional responsibilities.

Source: ParticleConversion.hpp.

template<typename TParticle>
void corsika::kokkos::export_particle_values(TParticle const &particle, CoordinateSystemPtr const &coordinateSystem, ParticleState &state)

Export particle values to the numerical representation used by transport.

This host-only conversion uses C8’s coordinate transformations and units: total energy in GeV, position in metres, time in seconds and dimensionless direction components. A particle without a weight getter has unit weight. No direction normalization, cut, random draw or identity allocation occurs.

Template Parameters:

TParticle – C8 particle interface providing getPDG, getEnergy, getPosition, getDirection and getTime; getWeight is optional.

Parameters:

  • particle – Source particle, not modified by coordinate conversion.

  • coordinateSystem – Non-null common coordinate system for the output.

  • state – Existing record whose value fields are replaced. Identity, generation, compatibility tags, medium and logical-node fields are preserved.

Throws:

std::invalid_argument – If the common coordinate system is null.

Pre:

The particle has a supported PDG code and finite physical values.

template<typename TParticle>
void corsika::kokkos::import_particle_values(ParticleState const &state, CoordinateSystemPtr const &coordinateSystem, TParticle &particle)

Import numerical values into an existing C8 particle, without adding a particle.

The record’s total energy is converted to kinetic energy using C8’s particle mass. Direction components are copied without normalization. This operation neither reads nor changes transport identity, logical-node or medium fields; their mapping belongs to the caller, not to this value conversion.

Note

A tagged native muon-pair cut must be handled before calling this ordinary on-shell conversion; compatibility tags do not relax its mass check.

Template Parameters:

TParticle – C8 particle interface providing setPID, setKineticEnergy, setDirection, setPosition and setTime; setWeight is optional.

Parameters:

  • state – Numerical input with energy in GeV, position in metres and time in seconds. The record is not modified.

  • coordinateSystem – Non-null common coordinate system of the record.

  • particle – Existing destination particle; its stack size is unchanged.

Throws:

  • std::invalid_argument – If the coordinate system is null or the PDG code is unknown. Other unsupported PDG codes retain C8’s conversion errors.

  • std::runtime_error – If total energy is below the C8 rest mass or a non-unit weight would be lost. These checks precede destination mutation.

Pre:

Values are finite and the PDG code is supported by C8. Direction is already appropriate for the caller’s transport algorithm.

Production state transfer

These templates use the topology associated with the current snapshot to retain the native particle’s logical node across the transfer. That topology and its native scene must remain alive and unchanged. to_device_state constructs a numerical record; import_particle inserts a native stack particle. Importing the logical node alone does not import physical values.

Source: RouterParticleConversion.hpp. The complete identity, cut and stack insertion contract is documented in Host and backend conversion.
