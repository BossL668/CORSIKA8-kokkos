Application interfaces

These host interfaces connect application-owned C8 objects to direct or coordinated execution. Declarations and public members below are generated from the headers at the reference baseline recorded in API reference. They describe the current integration API, not an upstream stability guarantee.

For the call sequence and argument meanings, read Execution selection and setup, Application data and lifetime contracts and Event execution and results. The configuration records on this page are C++ values; their default initializers are not a substitute for the application’s resolved command-line defaults.

Execution selection

Selection occurs before model construction and Kokkos initialization. Direct execution includes native C8, OpenMP and a single GPU. Coordinated execution uses the separate process coordinator. The returned selection retains device configuration but does not own a running device session.

Source: ExecutionSelection.hpp.

Run and event lifetimes

CascadeModule retains backend hooks across events. It borrows the native objects supplied during construction; those owners must outlive the module. shower creates event state, and CascadeEvent::cascade returns the adapter on which the application calls EAS.run(). The original native Cascade is constructed inside the native execution branch.

CascadeEvent also controls input, output and diagnostic lifecycle. Its constructor or destructor alone does not establish that a shower completed; use the completion contracts in Outputs and run checks.

Source: CascadeExtension.hpp.

Borrowed application context

CascadeGeometry holds references to the scene and typed geometry objects, alongside copied numerical configuration. CascadeContext groups geometry, outputs, processes, execution and diagnostic bindings. Copying these bundles does not transfer ownership of the native stack, models or writers. The native objects and any borrowed diagnostic snapshots must remain valid during use.

Source: CascadeContext.hpp. The component bundles and their argument map are described in Application data and lifetime contracts.

CascadeEventConfig carries physics/run settings used to configure events, including typed energies, cuts, thinning and primary identity. Native typed quantities remain on this host boundary; numerical conversion happens during preparation and transfer.

Prepared host inputs

PreparedCascade owns its exported environment through shared immutable storage; its numerical view borrows that storage. The native environment is still required for host tracking, CPU completion and output conversion. Prepared data is not a device upload, nor is it refreshed by later mutations of native objects. See Scene construction and snapshot export and Extending models and execution paths for preparation and reuse requirements.

Source: PreparedCascade.hpp.

Prepared host data for the production air runner. Numeric views borrow environmentStorage_; copies share the same owner. The original native environment and its model assignments must also stay alive and unchanged until transport, fallback and output have completed.
