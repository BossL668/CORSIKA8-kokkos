Developer guide

This part of the documentation explains how to change the existing CORSIKA 8 with Kokkos implementation and maintain it as C8, its physics dependencies and supported platforms evolve. It follows the development process: locate the responsible component, implement a change, verify it on the affected execution paths, and maintain compatibility with the surrounding framework.

The component chapters explain how the current system works. The pages here explain how to work on that system. They distinguish existing interfaces from recommendations for further integration with C8.

The separate API reference provides declarations and member documentation. Use it to look up a signature or type after locating the responsible component.

Development workflow

  1. Identify the behavior to change. Trace the application input to the responsible preparation, numerical or execution function. The file map and continuous-energy-loss example in Code organization and modification guide show how to locate its callers and tests.

  2. Prepare a reproducible build. Keep native and accelerated build directories separate. Record the C8 revision, dependency versions and backend configuration. Configuring development builds explains the targets and toolchain settings; Installation provides installation commands.

  3. Implement at the appropriate layer. Change data conversion when an input changes, the numerical implementation when a calculation changes, or the scheduler when work assignment changes. Reuse existing interfaces and shared functions; Extending environments and physics capabilities and Sharing numerical algorithms with native C8 give concrete examples.

  4. Validate the affected behavior. Start with controlled-input tests, then exercise the connected execution path. Use complete showers when the change affects physical distributions or event-level behavior. Testing and benchmarking explains how to select the comparison and timing scope.

  5. Prepare the change for review and maintenance. Explain the resulting behavior, affected callers and validation evidence. Update the relevant documentation. If an interface, dependency or persisted record changes, follow Maintaining compatibility with C8 and dependencies as well.

Maintenance principles

Native C8 constructs the scene and configured physics models. Preparation adapters make the required data available to numerical functions. Execution code manages storage, queues and scheduling. Keeping these responsibilities separate makes it possible to change a calculation without redesigning the application or implementing it separately for CUDA and HIP.

OpenMP, CUDA and HIP already use common Kokkos numerical implementations. Sharing with the native C8 path is more selective: some functions share source, while others use exported native data with separate calculations. Maintenance must therefore cover both shared functions and adapters between separately maintained implementations. The integration chapter identifies the remaining choices without treating them as decisions already adopted by the CORSIKA project.
