Photon-pair rejection exhaustion regression
==========================================

Production policy:
  - Keep the existing 64-attempt photon-pair rejection sampler and its RNG keys.
  - After exhaustion only, draw a fresh split quantile and invert the exported
    PROPOSAL photon-pair cumulative table on the current execution space.
  - Invalid weights, material data or rejection envelopes are errors, not
    ordinary exhaustion. Invalid/out-of-domain CDF queries retain the explicit
    CPU-fallback diagnostic. Never use the final rejected candidate as output.
  - The photon loss fraction remains v=1; the secondary electron fraction x is
    a separate query. Directions, LPM acceptance and thinning are unchanged.
  - Electron direct-pair asymmetry rho has no corresponding native interpolation
    table and is NOT changed by this photon-only fallback.

Build (OpenMP or CUDA configuration):
  cmake --build BUILD --target testPhotonPairSplitFallback
  BUILD/tests/accelerator/testPhotonPairSplitFallback TABLE_CACHE [N_PER_CELL]

The default is 256 samples per cell; the allowed maximum is 100000. The test
creates/reuses PROPOSAL tables under TABLE_CACHE (default pair_fallback_tables).
It uses the built execution space; a CUDA build requires a visible CUDA device.
Set OMP_NUM_THREADS to a fixed small value for an OpenMP run.

Coverage:
  Air N/O/Ar, 9 photon energies from 1.1 MeV to 1e11 MeV, and compile-time caps
  64, 1 and 0. Only the test instantiates the shorter caps: production has no
  CLI/runtime switch to reduce the rejection cap. The shorter caps exercise
  frequent/all-CDF paths which a few normal showers cannot be expected to hit.
  Compare accepted trials against the original keyed rejection sampler and
  CDF trials against the public PROPOSAL CalculateRho secondary sampler. Check
  draw identity, physical split bounds, energy conservation, direction norms,
  LPM-suppressed output and explicit invalid-input/table fallback.

Interpretation:
  The fallback reproduces the native interpolated CDF, not an exact analytic
  distribution. Near threshold its interpolation error can differ from that
  of the rejection sampler. Before LPM conditioning, an exhaustion probability
  q mixes the two laws as (1-q) f_rejection + q f_native. Zero exhaustions in a
  finite test does not prove q=0 everywhere. Do not lower the production cap
  based on the forced-exhaustion tests. Full-shower regression and performance
  evidence are needed in addition to this component test.

Validation, 2026-10-11 (baseline 3767dd98):
  OpenMP (4 threads, Core i9-14900HX) and CUDA (one RTX 4060 Laptop GPU):
  100000 samples/cell, 8100000 samples/backend, 3693289 forced CDF queries,
  8 invalid-input guards. Maximum absolute split difference from native
  CalculateRho: 7.22e-15. The normal cap-64 group had zero exhaustions;
  the largest observed accepted trial number was 20.
  Full c8_air_shower regression: 3 x e-100GeV, 2 x gamma-1TeV and
  1 x Fe56-215.4TeV per backend (12 seeded baseline/candidate pairs).
  Included 3-antenna CoREAS/ZHS radio; all checked profile, deposition,
  particle, interaction and radio arrays matched exactly. No new fallback
  counts. This is not a four-GPU/110-antenna production-scale validation.
  Serial GPU Fe shower time: 83.931 -> 84.071 s, excluding initialization.
  Small-shower timings fluctuated; repeated photon showers showed no stable
  slowdown. Do not claim a measured speedup. CUDA register use increased in
  some photon kernels, so other devices/workloads still need benchmarking.
  Compute Sanitizer was unavailable through the local WSL/WDDM interface;
  it is not counted as a passed check.
