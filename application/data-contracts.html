Application data and lifetime contracts

The run is connected with three calls immediately before the event loop. These are actual calls from main; the environment and models already exist here.

770  auto geometry =
771      backend.geometry(env, rootCS, injectionPos, surface_, step, showerAxis, dX);
772  auto defaults = air::make_cascade_defaults(
773      app, seed, eMax, beamCode, cut, prod_threshold, heHadronModelThreshold, multithin);
774  auto execution = backend.execution(geometry, defaults, emCascade, emContinuousProposal,
775                                     coreas, zhs, heCounted, leIntCounted, output);

geometry describes the scene through references, defaults contains configuration values, and execution retains the library driver across events. None of these calls advances a particle.

geometry(): borrow the existing scene

CascadeExtension::geometry(...) calls make_cascade_geometry(...) and returns CascadeGeometry<...> by value. Copying that bundle copies references to C8 objects; it does not copy the environment tree to a GPU.

Argument in main

Field in CascadeGeometry

Meaning

env

environment_

Reference to the native Environment<EnvironmentInterface> and its geometry/material tree.

rootCS

coordinates_

Reference to the coordinate-system pointer used for numerical export.

injectionPos

injectionPosition_

Native primary-injection point, retaining its units and coordinates.

surface_

surface_

Native surface reference used by the propagation setup.

step

propagationStep_

Radio propagation step, set to 1_m in this application. It is not the particle’s selected transport step.

showerAxis

showerAxis_

Native shower axis used for longitudinal projections.

dX

depthStep_

Profile bin width, 10_g / square(1_cm) here. It is not a sampled interaction depth.

The factory also copies the observation height, horizontal core coordinates and magnetic-field metadata from the previously configured RunEnvironmentConfig. The actual device field is obtained from the native environment’s model export during prepare_cascade(...).

The storage contract is visible in the declaration:

26  struct CascadeGeometry {
27    TEnvironment& environment_;
28    TCoordinates const& coordinates_;
29    TPosition const& injectionPosition_;
30    TSurface const& surface_;
31    TStep const& propagationStep_;
32    TAxis const& showerAxis_;
33    TDepth const& depthStep_;
34    double observationHeightM_;
35    double coreXM_;
36    double coreYM_;
37    std::array<double, 3> magneticFieldT_;
38  };

The referenced scene objects must remain alive through transport, CPU fallback and output. Changing a few fields in RunEnvironmentConfig does not replace the actual C8 environment.

make_cascade_defaults(): copy run settings

make_cascade_defaults(...) returns CascadeEventConfig. Its inputs are:

Input

Values read or stored

app

Parsed thinning fraction, automatic-weight selection, high-energy hadronic model name and maximum magnetic deflection angle.

seed, eMax, beamCode

Run seed, maximum configured primary energy and primary particle code. eMax has the native HEPEnergyType.

cut

Electron and muon kinetic-energy cuts, obtained with getElectronKineticECut() and getMuonKineticECut().

prod_threshold, heHadronModelThreshold

Native energy quantities for secondary production and the hadronic model transition.

multithin

Stored as keepZeroWeightParticles_.

This is a value object. It does not store a new primary particle or start a shower. CascadeApplication::cascade(...) later copies it and fills the event’s ordinal, output ID, actual primary energy and maximum weight. That distinction also supports a run whose primary energies are sampled over a range.

execution(): bind models and outputs for the run

backend.execution(...) receives geometry and defaults by value, then references to six existing model/counter objects and the output manager:

Arguments

Why the library needs them

emCascade, emContinuousProposal

Native interaction and continuous-process instances. They provide PROPOSAL calculator views for table export and the corresponding native process connections.

coreas, zhs

Radio process instances. Their observerCollection() methods supply the configured observer collections.

heCounted, leIntCounted

Existing hadronic interaction counters used for event diagnostics.

output

Existing OutputManager& used to register run-level timing and any additional backend output.

It creates SequenceModels, SequenceOutputs and CascadeMonitors bundles, then returns a CascadeModule<...>. The returned module contains its CascadeDriver, timing writer and binding/configuration state. The physical model objects and detector collections remain owned by the caller.

For example, the run-level model bundle contains references:

17  struct SequenceModels {
18    TC& coreas_;
19    TZ& zhs_;
20    TE& emCascade_;
21    TP& emContinuousProposal_;
22  };

Event-specific processes and writers are obtained from the actual ProcessSequence when the event executes. The application therefore does not pass every event-local object to execution(...). The Event execution and results page follows this lookup.

Where host objects become device data

The main application passes C8 objects to a host-side interface. GPU kernels receive numerical views and backend-managed storage later in the call chain:

Boundary

Returned data or state change

prepare_cascade(...)

Returns PreparedCascade<...>. It owns a shared reference to an exported environment snapshot, provides its EnvironmentDataView and prepares transport, radio, profile and physics-requirement configuration. It does not transport particles or initialize the backend.

nativeCalculatorViews()

The interaction and continuous models provide native calculator views. The runner requests them on first backend initialization.

beginProposalNative(...)

Exports/loads native table data and initializes device storage on the first call; resets shower-local backend state on reuse. Returns SessionBeginResult; see Backend preparation and session reuse.

PreparedCascade::environmentData_ borrows PreparedCascade::environmentStorage_. The original native environment also remains necessary for CPU processing and node-aware fallback. A changed environment is rejected when reusing an initialized EmRunSession; create a new session to upload a different scene.

Ownership rules for application authors

  • Keep CLI::App alive for the extension, and keep backend alive for the returned execution module.

  • Keep the native environment, coordinate system, geometry, model instances, counters, detectors and output manager alive while their bindings are used.

  • Keep the event, stack, tracking object and sequence alive until the returned adapter’s run() finishes. Its callbacks capture references.

  • Treat run-configuration values and borrowed object state differently: copying a configuration struct does not create independent models or writers.

Source references

The factories are in CascadeSupport.inl and CascadeExtension.inl. The receiving types are declared in CascadeContext.hpp, CascadeEventConfig.hpp and PreparedCascade.hpp.
